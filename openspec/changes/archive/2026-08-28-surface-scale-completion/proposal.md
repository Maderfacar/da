> 這是「介面方向改精品調」的**階段 2**，也是九項候選的收官。
> 階段 0（`2026-08-25-design-token-foundation`，已 archive）換色票與字體、建 token 層。
> 階段 1（`2026-08-27-color-completion`）把沒跟上的 36% 色彩收乾淨。
> 本階段處理**剩下的五項**：玻璃退場 · 表面 token 化 · 尺度 token 實際替換 ·
> 後台色票編輯 UI · 深色模式 · 版面重排。

## Why

階段 1 收官時，設計系統的**色相**已經只有一個真相來源，但另外三個維度還沒有：

### 一、玻璃是精品調裡最違和的殘留

`--da-glass-*` 三個 token（半透明底 + 古銅邊 + 雙層陰影）配上 `backdrop-filter: blur()`，
是 2020 年代的 glassmorphism 語彙。精品調（縞黑 · 骨白 · 古銅）的層級語言是
**實心表面 + 髮絲線 + 極淡陰影** —— 兩者疊在一起，卡片看起來既不通透也不紮實。

實測（2026-08-27，`app/` 下 `.vue` / `.css` / `.scss`）：

| 項目 | 處數 | 檔數 |
|------|------|------|
| `var(--da-glass-bg)` | 39 | — |
| `var(--da-glass-border)` | 34 | — |
| `var(--da-glass-shadow)` | 13 | — |
| **glass token 小計** | **86** | 31 |
| `backdrop-filter` | 65 | 37 |
| **合計** | **151** | **48** |

`backdrop-filter` 另有效能代價：它強制建立合成層並在每幀重新取樣背景，
是 `web/performance.md` 明列的 INP 殺手，而站上 30 處用的是 `blur(12px)`。

### 二、表面色是「階段 1 刻意留下的兩批殘留」

階段 1 的守衛裡有兩處**寫明是留給本階段**的豁免（`design-token-guards.spec.ts`）：

```
// ② **中性**的白／黑疊層（r === g === b）…… 全站約 40 條，
//    屬「表面疊層 token 化」（--surface-a* / --ink-a*）的範圍，不在色彩收尾階段。
// 中性色（白／黑／灰）與深色面暫時放行 —— 它們歸「尺度與表面 token」階段。
```

實測比註解裡的估計更多：

| 項目 | 實測 |
|------|------|
| 深色面藍黑家族（`#1a1a2e` 10 · `#161b22` 8 · `#1f2937` 5 · `#0f1115` 4 · `#2d2d4e` 4 · `#0d0f14` 3） | **34 處** |
| 中性疊層本地 SCSS 變數（`$border: rgba(255,255,255,.08)` 之類） | **79 條** |

深色面那 34 處是**藍黑**（hue 200–240°），縞黑 `#1A1917` 是**暖黑**（hue 40°）。
兩者並置時暖黑會顯得偏紅、藍黑會顯得偏冷 —— 這正是「admin 看起來跟乘客端不像同一個站」的原因之一。

**這兩批動的是同一批檔案**，與玻璃退場也高度重疊（`--da-glass-bg` 的 39 處有 8 處在深色 admin 頁）。
分成三個 wave 會把同一批檔案翻三次，所以綁一起做。

### 三、尺度 token 定義了一年，一處都沒替換

階段 0 的 `_design-tokens.css` B 區明寫「**只定義不替換**」。到今天仍是 0 替換，
而定義出來的階梯與實況嚴重對不上 —— **階段 0 的估計低估了 2.6 倍**：

| 維度 | 階段 0 估計 | 實測相異值 | 實測處數 |
|------|-----------|-----------|---------|
| `border-radius` | 12 種 | **31 種** | 656 |
| `z-index` | 13+ 種 | **29 種** | 76 |
| `box-shadow` | — | — | 79 |
| `transition` 時長 | — | 14 種 | 254 |

`z-index` 那 29 種從 `0` 到 `90000`，中間有 `9999` / `10000` / `1900` / `1200` / `1100` / `1050`
—— 那不是層級系統，那是「上次被蓋住所以加一個 9」的考古地層。

### 四、深色模式的位置一直是空的

`_theme-colors.css` 末尾留著一段：

> `:root.dark` 已移除 —— 其內容原本與 `:root` 一字不差…是死碼，
> 卻因為 `@nuxtjs/color-mode` 掛著而讓人誤以為有深色模式。**要做深色模式請另開變更。**

模組還掛著、成本已經付了，但功能不存在。而 admin 與司機端本來就整片深底 ——
真正缺的是**乘客端**的深色面，以及一個「深色的表面色是什麼」的定義。
這一項必須排在表面 token 化**之後**，否則沒有可切換的對象。

### 五、色票只能改程式碼

主題引擎（`shared/site-theme.ts`）在 2026-07-29 就上線了（`project-passenger-seasonal-theme` W1），
12 個 `--da-*` token 可由 Firestore 覆寫、按 `[data-da-theme]` 注入乘客端。
但**沒有後台 UI** —— 換季要嘛改 `scripts/migrate-site-themes.mjs` 重跑，要嘛手動改 Firestore。
引擎的 W2（admin UI）從那時起就是待辦。

## What Changes

五個 wave，各自獨立 commit，破圖可歸因到單一 wave（沿用階段 1 的 D6 紀律）。

### W1 — 玻璃退場 + 表面 token 化（151 + 34 + 79 = 264 處 / 約 90 檔）

- `--da-glass-*` 三個 token 下架，86 處改接 `--surface-raised` / `--hairline` / `--shadow-soft`
- `backdrop-filter` 65 處全數移除（含 `-webkit-` 前綴）
- 新增 `--surface-deep` / `--surface-deep-2` / `--surface-deep-3` 三個**絕對深色面** token，
  34 處藍黑改接（並從藍黑校正到暖黑家族）
- 79 條中性 SCSS 變數改走 `--surface-a*` / `--ink-a*`
- 關掉守衛裡兩處「暫時放行」，改成常態擋

### W2 — 尺度 token 實際替換（656 + 76 + 79 + 254 = 1,065 處）

- 圓角階梯**重定**（階段 0 那五個值蓋不住實測的 31 種），656 處替換
- `z-index` 29 種收成 6 層語意，76 處替換
- `box-shadow` 79 處收成三階
- `transition` 254 處時長改走 `--dur-*`、緩動改走 `--ease-out`
- 新增守衛擋「尺度字面值復活」

### W3 — 後台色票編輯 UI

`/admin/settings` 新增主題包編輯器：12 個 `--da-*` 色票即時預覽、對比度即時計算、
主題包 CRUD、切換生效主題。補上主題引擎缺的 W2。

### W4 — 深色模式

以 W1 的表面 token 為基礎，乘客端加入深色配色與切換（跟隨系統／手動）。

### W5 — 版面重排

精品調的版面語彙：尺度對比、非均勻節奏、編輯感留白。範圍限乘客端公開頁面。
