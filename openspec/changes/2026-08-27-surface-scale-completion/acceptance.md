## 零、先講白話：這一輪到底做了什麼

把「介面方向改精品調」的九項候選做完了最後五項。用一句話說：

> **在這之前，同一件事在站上有好幾個答案；現在只有一個，而且那個答案寫在一個檔案裡。**

具體來說，之前的狀況是這樣的 —— 一張卡片的圓角，有人寫 8px、有人寫 10px、有人寫 12px，
全站 31 種；一個「浮在最上面」的東西，有人寫 999、有人寫 9999、有人寫 90000，全站 29 種；
一條分隔線的顏色，有人寫 `rgba(255,255,255,.08)`、有人寫 `.06`、有人寫 `.1`，全站上千處。
這些不是設計決定，是「上一個人怎麼寫，下一個人就照抄再改一點」累積出來的地層。

現在它們全部指向同一組定義。**這件事對你的直接意義是：以後要調整整站的質感，
改的是一個檔案裡的幾行，不是去 129 個檔案裡找。**

另外四件是新東西：玻璃質感退場、後台可以自己改色票、乘客端有了深色模式、首頁版面重排。

## 三、我修掉的一個階段 1 缺陷（不是新做的，是既有的）

階段 1 為了解決「古銅在深底只有 3.11:1」，把 `[data-surface='dark']` 標在
**admin layout 的根節點**上。司機端沒問題（11 頁全深色），但 **admin 是 7 深 7 淺混用**：

- 深色頁：`orders` `settings` `users` `drivers` `notifications` `traffic` `war-room`
- 淺色頁：`dashboard` `audit-logs` `referral` `line-management` `drivers/[uid]` `settings/pin` `fare-sandbox`

那 7 個**淺色**頁的主色因此被解析成深底用的亮銅 —— **於骨白只有 1.82:1**（古銅是 4.58:1）。
admin 的主色用量是 165 處。

已修：標記改落在真正是深色表面的節點上。

> 要驗的話：`/admin/dashboard` 與 `/admin/audit-logs`（淺色頁）的主色應該是**深古銅**，
> `/admin/orders`（深色頁）應該是**亮銅**。之前兩者都是亮銅。

**教訓值得記**：作用域標記要標在「表面實際是什麼顏色」的節點上，
不是標在「這一端大致是深色」的節點上。「admin 是深色的」是一句對一半的話，而 CSS 繼承不接受對一半。

## 四、無須動作、但你該知道的

1. **這一輪關掉了兩個階段 1 刻意留下的守衛豁免。** 它們的註解本來就寫明是留給本階段的
   （「中性疊層…屬表面 token 化的範圍」「深色面暫時放行…歸尺度與表面 token 階段」）。
2. **註解裡的估計又低估了一個數量級。** 階段 1 寫「中性疊層約 40 條本地 SCSS 變數」，
   實測宣告 79 條、引用 343 處，而**行內寫法另有 884 處**。
   跟階段 1 的「只查 hex 會漏掉 rgba」是同一個教訓的第三次。
3. **階段 0 的圓角階梯是照想像定的。** 它寫「12 種值」，實測 31 種；
   它定的 `--r-card: 5px` 全站只有 4 次、`--r-sm: 3px` 只有 3 次，
   而真正的量體（10px×88、12px×62）在那個階梯裡根本沒有對應階。
4. **新增了 9 條守衛，每一條都注入違規證明會紅、還原證明會綠。**
   z-index 那條另外證明了「區域堆疊 `z-index: 5`」不會誤觸發 —— 守衛要準，不是要嚴。
5. **richmenu 字型仍需你手動重選**（階段 0 留尾，只能在 admin 後台操作）。

6. **「同一個顏色有第 N 種寫法」這件事，這一輪撞了七次。** 值得記，因為它每次都長得不一樣，
   而且**四次是比對 build 產物才發現的**（那時原始碼掃描與守衛全是綠的）：

   | # | 漏掉的寫法 | 怎麼發現的 |
   |---|-----------|-----------|
   | 1 | `rgba(212,134,10,.18)` 逗號式 | 階段 1 盤點時多查一種寫法；rgb 形式比 hex 多**三倍** |
   | 2 | `rgba(26,26,46,.92)` | **比對產物** —— 原始碼看不出是藍黑，要等 Sass 壓成 `#1a1a2eeb` |
   | 3 | `#00000094` 8 碼 hex | 最後一次全掃原始碼；`#[0-9a-f]{6}\b` 的 `\b` 在第 7 字元不成立 |
   | 4 | `#eee` 3 碼 hex | 守衛改全禁式，一上就抓到 |
   | 5 | `background: white` 關鍵字 | **比對產物** —— 不含 `#` 也不含 `rgb(`，六道守衛全不認得 |
   | 6 | 關鍵字寫在函式值裡 | **比對產物** —— 守衛只比對「屬性後緊接關鍵字」 |
   | 7 | `rgb(0 0 0 / 60%)` 空格分隔 | **比對產物** —— 所有 regex 都寫成逗號式 |

   結論兩句：**守衛全綠只代表「我想得到的病沒發生」**；
   **盤點一種顏色前，先把它所有可能的寫法列出來，不要先假設病長什麼樣。**
   守衛最後改成「`<style>` 內全禁字面色碼 + 兩個具名例外」才收斂 —— 全禁比列舉可靠。

7. **另一顆同源的**：玻璃 token 的「用法」88 處清光、守衛全綠，但三個**定義**還留在
   `_theme-colors.css` —— 那個檔在守衛的 `TOKEN_SOURCES` 裡被跳過（那是刻意的，
   token 定義處本來就該寫字面值）。也是比對產物才發現。**定義與用法要分開守。**

8. **站上其實有第三套調色盤，只是因為夠灰所以一直沒被當成顏色。**
   Element Plus 與 Tailwind 的預設灰藍（`#dcdfe6` `#606266` `#909399` `#6b7280`…）
   被**手抄**進元件裡 **155 處**，散在 admin 子頁、2FA 兩頁、車輛審核、公告彈窗、富文本樣式。
   階段 1 只修了 EP 的 `$colors` map（編譯期常數），看不到手抄的字面值。

9. **W5 有兩個我自己修掉的 bug，第二個特別值得記**：
   `grid-row: 1 / -1` 在沒有 `grid-template-rows` 的 grid 上不生效 ——
   `-1` 指的是**顯式**格線的最後一條，於是塌成 `1 / 2`。
   修完之後 CSS 確實進了產物、33 張基線也全綠，**因為基線是我自己剛重拍的**。
   是逐張看圖看到空隙沒變，才回頭量 DOM 的。
   **視覺基線擋的是回歸，不是「這次做對了」。**

### 字級階梯不是我定的

`scss-tool/typography.scss` 早就拍板過「最小字級 12px，不再使用 9 / 10 / 11px」
「body 從混用的 13/14 統一提到 15」。同一份檔案還寫著
「舊代碼 11px 仍存在 100+ 處，後續以 PR 漸進收斂」——
**那個收斂從來沒發生**：實測 444 處低於它自訂的最小值，而整套 16 個 token 全站只被引用 8 次。
我做的是把 2,167 處實際接上去，不是重新發明階梯。

如果你覺得某些地方（例如 admin 密集表格）12px 還是太大，那是**階梯的一階要不要拆**的問題，
改 `_design-tokens.css` 一行即可，不必回頭改 1,309 個點。這正是這輪的重點。

### 一個我自己抓到並修掉的破圖

字級階梯把兩端側欄的字標從 28px 吸到 32px，而側欄可用寬只有 240px ——
「DEST·ANYWHERE」直接被切成「DEST·ANYWHER」。降一階修好。
**是逐張看基線截圖抓到的**，不是測試抓到的：33/33 全綠只代表跟上一次一樣。
